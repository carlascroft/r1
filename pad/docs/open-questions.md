# Open questions

These are Carl's to settle. Raise them when the build reaches them. Do not choose
quietly and do not fill them with a plausible default.

**The name.** `pad.` is a placeholder. His tools are lowercase with a full stop —
`send.`, `proof.`, `place.`, `loft.`, `foil.`, `nap.`, `chorus.`, `schlep.`.

**The colour.** The mockup puts it in the orange object family. The argument for orange
is that a control surface is an object; the argument against is that it is really a
tool, and the tool face is paper, which the calculator has already spent. One custom
property, one edit.

**Absolute or relative continuous controls.** The mockup shows `0.35 pt`, which assumes
the Mac can read the current value out of Illustrator. If it cannot, the control becomes
relative and the screen shows a delta instead. This changes the face, so ask before
building milestone 5.

**Whether an unassigned slot is drawn.** The mockup draws it, on the reasoning that the
grid is the constant. The gap might be more honest.

**Where the page indicator lives.** Top band with the app name, or bottom band with the
status.

**What the top band names.** The application being controlled, or the pad.

**Which nine actions.** The Illustrator set in `config/keypads.example.json` is a
plausible nine, not a considered nine. Carl works in Illustrator daily and knows which
shortcuts he actually reaches for. Ask rather than assume.

**Whether this stays one creation.** It could be a face inside the existing suite
launcher rather than a separate install. That decision affects the shared runtime.
